## Part A. 시청 전 — 프리뷰

> 강의를 보기 전에 5분만 투자해서 아래를 읽어두세요.
> 머릿속에 "관찰 프레임"을 설치하면, 2시간 라이브에서 핵심을 놓치지 않습니다.

### 이 강의에서 얻을 수 있는 것

이 강의는 단순한 "바이브 코딩 데모"가 아닙니다. 토비는 다음을 **실시간으로** 보여줍니다:

- 맨땅(모든 설정 리셋)에서 시작하는 이유와 방법
- AI에게 일을 시키되, **주도권을 잃지 않는** 대화 패턴
- AI가 만든 코드를 검증하고 교정하는 구체적 기준
- 가이드라인(CLAUDE.md)을 **점진적으로 빌드업**하는 전략
- 프로젝트 생성 → 도메인 → 서비스 → 컨트롤러 → 프론트엔드 → 리뷰까지의 전체 사이클

### 에이전틱 프로그래밍 핵심 원칙 7가지

강의 전체에서 추출한 원칙입니다. 시청하면서 이 원칙이 적용되는 순간을 포착해보세요.

| # | 원칙 | 왜? | 적용 시점 |
|---|------|-----|-----------|
| 1 | **한 달에 한 번 리셋하라** | 플러그인, 설정이 쌓이면 오히려 성능이 떨어지고 제어 불능이 됨. 모델 업데이트 시 기존 설정이 역효과를 낼 수 있음 | 새 모델 출시 시, 설정이 복잡해졌다고 느낄 때 |
| 2 | **AI에게 먼저 시키고, 결과를 교정하라** | AI의 디폴트 행동을 먼저 관찰해야 "무엇을 교정할지" 알 수 있음. 선행 지시를 과도하게 하면 오히려 AI 능력을 제한함 | 새 레이어/기능을 처음 만들 때 |
| 3 | **스프링 이니셜라이저를 사용하라** | AI가 직접 프로젝트를 구성하면 Gradle 버전/Java 버전 호환성 문제 발생. 스프링 개발팀이 검증한 최적 조합을 활용해야 함 | 프로젝트 초기 생성 시 |
| 4 | **플랜 모드로 먼저 확인하라** | 코드 생성 전에 AI가 올바르게 이해했는지, 어떤 버전/기술을 쓰려는지 검증 가능. 잘못된 방향으로 코드가 생성되면 되돌리기 비용이 큼 | 새로운 작업을 시작할 때마다 |
| 5 | **엔티티 하나로 전체 레이어를 관통하라** | 도메인 → 리포지토리 → 서비스 → 컨트롤러를 하나의 엔티티로 한 사이클 돌리면서 각 레이어의 개발 규칙을 확립. 이후 나머지 엔티티는 이 규칙을 따르게 됨 | 프로젝트 초기 가이드라인 빌드업 시 |
| 6 | **CLAUDE.md에는 AI가 못하는 것만 넣어라** | AI가 이미 잘하는 것까지 지시하면 파일이 비대해지고 오히려 중요한 지시를 무시함. "롬복으로 게터 만들어라" 같은 건 불필요 | CLAUDE.md 작성/리뷰 시 |
| 7 | **테스트 정책을 명시하라** | AI의 디폴트: 기능만 만들고 테스트 생략, 또는 도메인 테스트에 JPA를 끌어옴, 서비스 테스트는 무조건 Mock. 이 습관을 교정하지 않으면 테스트 품질이 계속 낮음 | 첫 테스트 코드가 생성된 직후 |

### AI 교정 패턴 카탈로그

**AI가 반복적으로 틀리는 지점**과 **교정 방법**을 정리했습니다. 자신의 프로젝트에서도 동일한 패턴이 나타나는지 확인해보세요.

#### 패턴 1: 프로젝트 생성 시 구버전 사용

- **증상**: Spring Boot 3.x, Java 17 등 학습 데이터 기준의 구버전으로 프로젝트 구성
- **원인**: AI 모델의 학습 데이터 시점 한계
- **교정**: 버전을 명시하고, 스프링 이니셜라이저 사용을 지시
- **예방**: 프로젝트 생성 스킬(Skill)을 만들어 자동화

#### 패턴 2: 도메인 테스트에 JPA 의존성 투입

- **증상**: 도메인 엔티티 단위 테스트에 `@DataJpaTest`, `EntityManager` 등 사용
- **원인**: AI가 JPA 엔티티와 도메인 객체를 구분하지 못함
- **교정**: "도메인 엔티티는 순수 단위 테스트, JPA 사용 금지" 명시
- **예방**: CLAUDE.md에 테스트 정책 기록

#### 패턴 3: 서비스 테스트를 무조건 Mock으로 생성

- **증상**: 서비스 테스트에서 리포지토리를 Mockito로 모킹
- **원인**: 인터넷의 대다수 예제가 Mock 방식
- **교정**: "서비스 테스트는 @SpringBootTest + H2 통합 테스트" 명시
- **예방**: CLAUDE.md에 레이어별 테스트 정책 기록

#### 패턴 4: 테스트 미생성 / 실행 미수행

- **증상**: 기능 코드만 만들고 테스트를 만들지 않음, 또는 만들고 실행 안 함
- **원인**: AI의 디폴트 행동은 "요청한 것만 수행"
- **교정**: "기능 구현 시 테스트도 같이 만들고 실행까지 해라"
- **예방**: CLAUDE.md에 상시 규칙으로 등록

#### 패턴 5: 필수 항목 검증 누락

- **증상**: 엔티티 생성자에서 필수 필드 null 체크 등 검증 코드 없음
- **원인**: 인터넷의 평균적인 스프링 코드 수준으로 생성
- **교정**: 코드 리뷰 시 발견 → 보강 요청
- **예방**: 개발 가이드라인에 검증 정책 포함

#### 패턴 6: 스프링부트 4 미적응 (최신 버전 문제)

- **증상**: Jackson 패키지명 변경, 테스트 모듈 분리 등 인식 못함
- **원인**: 학습 데이터에 최신 버전 미반영
- **교정**: 에러 발생 시 AI가 웹 검색으로 자체 해결 (대체로 잘함)
- **예방**: 반복 발생 시 CLAUDE.md에 변경사항 기록

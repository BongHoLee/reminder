# 토비의 클로드 코드와 스프링 개발하기 - 강의 2

> 클로드 코드의 동작 원리(에이전트 루프, 도구)를 이해하고, 스킬/서브 에이전트/에이전트 팀을 활용하는 방법을 다루는 강의

---

## 1. 강의 소개 [00:06]

지난번에 스프링을 사용하시는 개발자가 클로드 코드 처음 시작할 때 막연하게 느껴질 수 있는 부분에 대해 개념을 설명드렸고요. 오늘은 한 2일차 정도 됐다고 생각하고, 클로드 코드를 잘 활용하는 방법에 대해서 몇 가지 팁을 드리고 기억하시면 좋을 만한 내용들도 설명드리려고 합니다.

---

## 2. 에이전틱 코딩의 동작 원리 [02:07]

### 클로드 vs 클로드 코드

많은 분들이 클로드하고 클로드 코드하고 그냥 섞어서 얘기하세요. 정확하게는 "클로드 코드를 사용해서 개발합니다"라고 해야 맞습니다. 클로드 코드, 커서, 코덱스 같은 도구들을 통칭해서 **에이전틱 코딩 툴**이라고 부릅니다.

### 클로드 코드 공식 문서의 "작동 방식" [03:08]

클로드 코드 공식 웹사이트에 **작동 방식** 부분을 먼저 잘 읽어 보라고 말씀드려요. 이거를 이해하는 게 되게 중요합니다.

에이전트라는 건 우리가 사람한테 "너 이런 작업을 해 와" 하면 알아서 작업을 수행하고 결과를 가져오잖아요. AI한테도 그런 방식으로 일을 시키는 거죠.

### 에이전트 루프 [04:09]

에이전트 루프가 돌아갑니다. 루프란 반복한다는 거죠. 뭘 반복하냐면:

1. **컨텍스트 수집** - 작업에 필요한 맥락 정보 모으기
2. **액션 수행** - 도구를 사용해서 작업 실행
3. **결과 검증** - 결과를 확인하고 더 해야 될 게 있는지 판단

이 세 가지를 프롬프트의 요구를 다 수행할 때까지 반복하는 거예요.

## 3. 도구(Tools)의 이해 [06:13]

### AI는 혼자 코딩을 못 한다

AI한테 "내 컴퓨터에 프로젝트 만들어 줘" 하면 뭐라고 답하겠습니까? "나는 사용자의 컴퓨터에 접근할 수 없습니다." 당연히 못 하죠. 그래서 **도구(Tools)**가 필요한 겁니다.

### 도구의 동작 방식 [07:15]

클로드 코드가 AI한테 "내가 이런 도구를 사용할 수 있어"라는 걸 보냅니다. 그러면 AI가 "그러면 이 도구를 써서 이런 작업을 해 봐"라고 알려주는 거죠. 실제 도구를 실행하는 건 **클로드 코드**가 하는 거예요. 클로드 코드는 내 컴퓨터에 깔려 있으니까, 권한만 줬다면 굉장히 다양한 일을 할 수 있습니다.

> 여러분이 클로드 코드를 쓰면서 앞에 동그라미 아이콘 붙어서 돌아가는 거 볼 때마다 **"아, 클로드 코드의 이런 도구를 AI가 사용하라고 해서 지금 실행하고 있구나"**라고 이해하시면 됩니다.

### 기본 내장 도구 목록 [20:29]

클로드 코드한테 **"내가 가지고 있는 도구가 어떤 건지 알려 줘"**라고 물어보면 됩니다. 사람들이 이걸 잘 안 하시더라고요.

기본 도구들:
- **Bash** - 쉘에서 뭐든지 실행할 수 있는 도구
- **Read** - 파일 읽기
- **Write** - 새로운 파일 쓰기/덮어쓰기
- **Edit** - 파일의 문자열 치환
- **Glob** - 패턴을 이용한 파일 검색
- **Grep** - 파일 내부 내용 검색
- **Skill** - 스킬 실행
- **Agent** - 에이전트 실행
- **WebSearch / WebFetch** - 웹 검색 및 내용 가져오기
- **Explorer** - 코드 분석용 에이전트 (병렬 실행 가능)

### 도구를 명시적으로 지정하면 더 잘한다 [25:33]

도구를 이해하는 게 왜 필요하냐면, **명시적으로 이야기해 주면 훨씬 더 일을 잘하는 경우가 많아요**. 예를 들어 Explorer 에이전트는 파일 분석에 뛰어난데, 지정하지 않으면 그냥 Glob이나 Grep만 쓰기도 해요. 명시적으로 "Explorer를 사용해서 분석해 줘"라고 하고, "병렬로 10개쯤 띄워서 작업해"라고 하면 정말 그렇게 해 줍니다.

## 4. 플러그인 설치와 보안 [28:38]

### 절대 좋다는 거 다 설치하지 마세요 [18:28]

갑자기 "이 명령 실행하면 에이전트 150개, 스킬 1500개를 설치해 드립니다" 막 이런 거 하거든요. 그런 거 깔고 나면 여러분의 컨텍스트는 어마어마하게 지저분해지고 성능은 엄청 떨어집니다.

> **인텔리제이에 플러그인 300개 깔면 개발이 좋아지나요?** 아닌 거 다 아시잖아요. 마찬가지입니다.

### 오피셜 플러그인부터 시작 [29:38]

`claude-official-plugins` 리포지토리에서 시작하세요. 엔트로픽 클로드 코드 팀이 관리하고, 충분히 검증된 것들입니다.

추천 초기 설치 목록:
- **RalphLoop** - 실무에서 제일 많이 쓰는 것 중 하나
- **Skill Creator** - 스킬을 쉽게 만들어 주는 도구
- **Exploratory Output Style** - AI 대화 중 인사이트를 중간중간 보여줌 (무조건 켜 놓으세요)
- **Plugin Dev** - 플러그인 직접 만들 때 필요

### 보안 주의사항 [19:28]

플러그인은 여러분의 컴퓨터를 해킹하는데 아주 유용한 도구거든요. 로컬에서 뭔가를 실행할 수 있는 능력을 가진 클로드 코드에 악의적인 프롬프트를 심어 놓으면 중요 정보를 뽑아가고 원격 전송까지 시켜 버릴 수 있습니다. **충분히 검증된 플러그인만 사용하시고, 그 이상은 직접 만들어 쓰는 게 훨씬 낫습니다.**

## 5. 스킬(Skill) 만들기 실습 [34:42]

### 스킬이란?

스킬은 엄청 대단한 거 같다고 생각하시는데 **그냥 별거 아니에요**. 여러분이 에이전틱 툴에서 사용하는 기능을 **프롬프트 재사용**하게 만들어 준 겁니다. 메소드 하나로 만들어 놨다 이렇게 생각하시면 됩니다.

### 스프링 이니셜라이저 스킬 만들기 [36:48]

Skill Creator 플러그인을 사용해서 "스프링 부트 프로젝트를 생성하는 스킬을 만들어 줘"라고 요청합니다.

프롬프트에 포함시킨 요구사항:
- 스프링 이니셜라이저를 이용해서 진행
- 스프링부트 버전은 사용 가능한 것을 보여주고 선택하게
- **AskUserQuestion** 도구를 사용해서 선택형 UI로 만들어 줘
- 자바 버전도 물어보기
- Gradle Kotlin DSL은 물어보지 말고 고정
- 아티팩트 이름은 현재 폴더 이름을 디폴트로
- 패키지 이름은 `toby.ai.{아티팩트이름}` 디폴트
- 디펜던시는 그룹별로 선택 가능하게

> 만들어진 스킬은 `/spring-initializer`처럼 슬래시 커맨드로도 실행할 수 있고, 프롬프트로 요구하면 AI가 알아서 해당 스킬을 실행하기도 합니다.

### 스킬의 저장 위치 [45:07]

- **유저 레벨** (`~/.claude/`) - 어떤 프로젝트에서든 항상 사용 가능
- **프로젝트 레벨** (프로젝트 내 `.claude/`) - 해당 프로젝트에서만 사용, git으로 팀과 공유 가능

## 6. 컨텍스트(Context) 관리 [43:03]

### 컨텍스트의 구성

매번 AI한테 보내지는 컨텍스트에는 다음이 포함됩니다:

1. **시스템 프롬프트** - 클로드 코드 팀이 미리 세팅한 기본 지침
2. **대화 히스토리** - 지금까지 주고받은 모든 메시지
3. **도구 목록** - 기본 도구 + 플러그인으로 추가한 도구

> 이게 많아지면 AI가 점점 더 일하는 효율이 떨어집니다.

### 스킬 vs MCP의 컨텍스트 영향 [53:14]

- **MCP**: 도구 목록을 너무 복잡하게 만들어서 보냄 → 컨텍스트를 쓸데없이 많이 잡아먹음
- **스킬**: 도구 목록에 간략하게만 들어감 → 훨씬 가벼움
- 하지만 스킬 실행 중 AI랑 주고받은 대화는 히스토리에 계속 남음

## 7. 서브 에이전트: 컨텍스트를 오염시키지 않는 작업 [54:15]

### 왜 서브 에이전트가 필요한가?

현재 개발과 직접 관련 없는 것들이 대화 히스토리에 계속 남아 있으면 **AI가 일을 잘 못 해요**. 서브 에이전트는 **세션을 분리해서** 작업을 시키고, 요약된 결과만 받아오기 때문에 현재 컨텍스트를 깔끔하게 유지할 수 있습니다.

### 코드 품질 분석 에이전트 만들기 [58:21]

코드를 분석해서 가독성, 아키텍처, 테스트, 보안 등 여러 분야로 분석하고, 각각 점수를 A~F 등급으로 매기는 에이전트를 만듭니다.

결과 예시:
- 전체 81점 B등급
- 규칙 준수 양호, 가독성 약간 떨어짐
- 크리티컬 이슈: 컨트롤러에서 리포지토리 직접 주입 (아키텍처 위반)
- N+1 쿼리 문제 발견
- 모범 사례도 함께 보여줌

> 이런 에이전트는 백그라운드에서 실행하고, 나는 다른 작업을 계속할 수 있습니다.

## 8. 에이전트 팀: TDD 실습 [1:02:31]

### 에이전트 팀이란?

서브 에이전트는 메인 세션에서 에이전트 부르고 응답받고를 반복하는 구조지만, **에이전트 팀은 만들어진 에이전트들끼리도 서로 커뮤니케이션**할 수 있습니다.

### TDD 에이전트 팀 구성

- **Lead** (팀 리드) - 개발 요구사항을 받아서 태스크 분할, 단계별 지시
- **Red** - 실패하는 테스트 작성 → 실행해서 실패 확인
- **Green** - 실패하는 테스트를 성공시키기 위한 최소한의 코드만 작성
- **Refactor** - 작성된 코드 정리

> tmux를 이용해서 화면을 분할하고 각 에이전트 하나마다 창을 할당해서 보여줍니다. 데모할 때 보여주면 개발자들이 다들 너무 좋아하시더라고요.

### IDE 연결로 코드 리뷰 [1:15:50]

`/ide` 명령으로 인텔리제이와 연결하면, 에이전트가 코드를 변경할 때 인텔리제이에서 변경 내역을 보면서 수락/거부할 수 있습니다.

> TDD 학습용으로 되게 좋고, 초기 개발에서 내가 원하는 스타일로 만드는지 검증하면서 진행할 때 굉장히 편리합니다.

## 9. 품질 분석 → 이슈 등록 → TDD 수정 워크플로우 [1:22:58]

### 전체 워크플로우

1. **코드 품질 분석 에이전트** 실행 → 이슈 목록 도출
2. 이슈를 **GitHub Issues로 등록** 요청 (혼자면 로컬에 만들기도 함)
3. 이슈 하나씩 **TDD 방식으로 수정** 요청
   - 문제가 되는 상황의 실패하는 테스트를 먼저 만들고
   - 그 다음 수정

> N+1 쿼리를 실패하는 테스트로 만들어서 검증하도록 하는 거, 클로드 코드가 기가 막히게 잘 만들어 줍니다. 저도 그걸 보고 배웠어요.

### 멀티 모델 협업 [1:30:13]

클로드 코드한테 "코덱스를 호출해서 작업을 수행하고 결과를 돌려받는 스킬을 만들어 줘"라고 하면 잘 만들어 줍니다. 이걸 써서:

1. **코덱스한테 코드 리뷰** 시키기 → 크리티컬 이슈 지적
2. **클로드 코드한테 반론** 요청 → "코덱스가 이렇게 지적했는데 동의하니? 아닌 건 반박해 봐"
3. 둘이 **토론**을 거쳐서 코드를 다듬어 나감

## 10. 핵심 정리 및 마무리 [1:28:09]

### AI 코딩에서 TDD가 중요한 이유

AI한테 작업하라고 하면 한 번에 너무 많은 걸 한꺼번에 해요. 우리 감각으로 했던 좀 더 작은 단위로 차근차근 하면서 관례도 만들고 다듬어 나가고 싶다면, **TDD 사이클을 이용하면 제일 좋습니다**.

확신이 생기면 범위를 점점 크게 하면 됩니다. API 테스트 레벨에서 TDD를 진행해 줘, 이렇게 요구할 수도 있어요.

### 도구 업그레이드의 필요성 [1:29:11]

모델이 좋아지면 기존에 만들어 놨던 도구가 쓸모없어지는 상황이 옵니다. 그래서 저는 `.claude`를 매번 리셋하고, 레퍼런스 프로젝트를 하나 가지고 "이제는 이 정도까지는 알아서 해 주네" 확인하며 빌드업합니다.

### 자기만의 도구 세트 갖추기

> AI가 일을 더 잘할 수 있는 환경을 내가 잘 꾸며 주고, 끊임없이 개선하는 시도를 해야 됩니다. 그게 에이전틱 코딩 도구를 사용해서 개발을 잘할 수 있는 방법입니다.

# 토비의 클로드 코드와 스프링 개발하기 - 강의 4

> Ralph(랄프) 플러그인을 활용한 PRD 작성과 Ralph Loop, 워크플로우 도구 비교(플랜 모드/Superpowers/Ralph), 프롬프트 엔지니어링 팁을 다루는 강의

---

## 1. 강의 소개 및 퍼미션 스킵 모드 [00:05]

클로드 코드를 이용해 스프링앱 개발하기 라이브 네 번째 시간입니다. 지난번에 마무리하지 못했던 내용을 오늘 조금만 진행하겠습니다.

### Dangerously Skip Permissions

클로드 코드가 매번 외부 명령을 실행할 때 확인을 받는 게 번거롭습니다. `--dangerously-skip-permissions` 옵션을 주면 전부 생략됩니다. 위험하지만 많은 분들이 켜고 쓰시는 옵션입니다.

> 사실 퍼미션을 확인한다고 하더라도 거의 읽지도 않고 기계적으로 YES 해 버립니다. 그래서 문제가 있어요.

운영 서버 연결 지점이 없고, 위험한 명령을 막아 놓은 상태라면 과감하게 써볼 수 있습니다. 저는 엘리어스로 짧은 명령으로 등록해서 씁니다.

## 2. 터미널 환경: Zellij 정착 [03:10]

고스티에서 **Zellij(시먹스)**로 완전히 갈아탔습니다. 2주 사용했는데 너무 좋아요.

### AI에게 새 도구 학습시키기

AI가 Zellij를 모르면 웹사이트를 주고 학습시킵니다. 한번 학습하면 잘 하지만 세션 종료 시 까먹으니까 **스킬로 만들어 두세요**.

## 3. 스킬의 두 가지 활용법 [10:16]

### 용도 1: 워크플로우 자동화
반복되는 프롬프트를 간단한 명령으로 실행. (예: 스프링 프로젝트 생성)

### 용도 2: 레퍼런스 (지식 저장)
AI가 모르거나 우리 팀만의 관례를 저장하는 용도.

예시:
- **스프링부트 4에서 달라진 점** → 스킬에 저장하면 개발 시 자동 참조
- **Zellij 사용법** → 학습 후 스킬로 만들어 세션 간 유지

> 유명한 스킬은 범용적이지만, **자기만의 스킬**을 잘 만들어 두시는 게 퍼포먼스를 올리는 데 되게 좋습니다.

## 4. 플러그인 구성 (실전) [14:20]

### 제가 쓰는 플러그인 목록

- **클로드 오피셜 플러그인** - 100개 이상, 오토 업데이트 권장
- **Superpowers** - 깃스타 4만+, 브레인스토밍~구현 9단계
- **Ralph Skills** - PRD 작성 + Ralph Loop
- **Firecrawl** - 종합적 웹 크롤링/검색
- **토비 플러그인** - 직접 만든 것들 (코드 품질, 분석, TDD 팀, 퍼미션 머지 등)

### 오마이 클로드 코드에 대해

되게 많은 기능을 해 주지만, **클로드 코드 입문 단계에서는 아직 쓰지 마세요**. 깔면 훅도 많이 들어가고 스킬도 많이 들어가서, 여러분이 알던 사용 방식이 잘 안 먹을 수 있어요. 감을 잡은 후에 살펴보시면 괜찮습니다.

## 5. 워크플로우 도구 3가지 비교 [30:45]

| 도구 | 적합한 상황 | 특징 |
|------|------------|------|
| **플랜 모드** | 단순한 수정, 잘 아는 작업 | 가볍고 빠르고 간단, 플러그인 불필요 |

> 3분이면 끝날 것 같은데 Superpowers 쓰면 30분 걸릴 수도 있어요. 그때는 Ralph PRD나 플랜 모드를 쓰면 됩니다.

## 6. Ralph 플러그인 상세 [07:13]

### Ralph란?

심슨에 나오는 캐릭터에서 이름을 따왔는데, 우직하게 실패해도 계속 다시 시도하는 특징을 가진 캐릭터입니다.

### AI가 작업을 중도 포기하는 문제

AI한테 작업을 시키면 작업이 길어지면 **하다가 갑자기 중단**해 버립니다. 기준을 줬음에도 불구하고. 그래서 **완료될 때까지 반복**시키는 게 Ralph Loop의 핵심 개념입니다.

## 7. Ralph PRD 실습: 통계 기능 추가 [24:40]

### PRD 스킬 사용법

```
/prd 통계 기능을 추가해 줘. 클릭 통계를 차트로 보여주는 페이지와 사이드바 내비게이션
```

이렇게 하면:
1. **명확화 질문을 딱 한 번**만 함 (Superpowers처럼 여러 번 왕복하지 않음)
   - 어떤 통계를 보여줄 것인가?
   - 통계 페이지 위치는?
   - 사이드바 스타일은?
   - 날짜 범위 선택은?
   - 차트 라이브러리는?
2. **유저 스토리** 형태로 정리 (사용자 관점의 요구사항)
3. 각 유저 스토리에 **인수 조건(Acceptance Criteria)** 포함
4. 기능 요구사항 정리 + 범위 밖 아이디어 제안

## 8. Ralph Loop: 완료될 때까지 반복 [36:57]

### 기본 개념

AI한테 작업을 시키고 → 완료 조건을 체크 → 안 됐으면 같은 프롬프트로 다시 시키는 **무한 루프**. 조건이 만족되면 빠져나옵니다.

### 두 가지 실행 방식

1. **쉘 스크립트 방식 (ralph.sh)** - 매 루프마다 클로드 코드를 새로 시작 (컨텍스트 초기화)
2. **플러그인 방식 (오피셜 플러그인)** - 컨텍스트 유지한 채 루프 반복

> 저는 컨텍스트 유지되는 플러그인 방식을 선호합니다. 작업 흐름이 잘 보이고, 컨텍스트가 넉넉하니까요.

### 실행 예시

```
/ralph-loop @prompt.md --completion-promise "COMPLETE" --max-turns 30
```

- `prompt.md` - 작업 요구사항 + PRD JSON 참조 + 완료 시 "COMPLETE" 출력 지시
- `--completion-promise` - 이 문자열이 출력되면 루프 종료
- `--max-turns` - 무한 루프 방지용 최대 반복 횟수

### PRD → JSON → Ralph Loop 흐름

1. `/prd`로 유저 스토리 + 인수 조건 작성
2. `/ralph`로 PRD를 **JSON 형식으로 변환** (각 유저 스토리에 `pass: false` 플래그)
3. Ralph Loop 실행 → 유저 스토리 하나씩 개발 → 인수 조건 충족 시 `pass: true`로 변경
4. 모든 유저 스토리가 `pass: true`가 되면 "COMPLETE" 출력 → 루프 종료

### Ralph Loop의 한계와 발전

- **단점**: 매번 똑같은 프롬프트를 반복. 새로운 시도가 필요한 상황에서 프롬프트 자체가 발전하지 않음
- **해결**: 프롬프트 자체를 업그레이드해 주는 스킬들이 존재 (다음 루프에서 더 나은 프롬프트를 생성)

### 다른 활용 예시

- 테스트 커버리지를 90%까지 올리기: "커버리지가 90% 될 때까지 필요한 테스트를 계속 추가해 줘"
- 복잡한 알고리즘 탐색: 성공할 때까지 여러 접근법을 시도

## 9. 프로젝트 분석과 탐색 단계 [12:21]

새 세션을 시작하면 AI는 프로젝트에 뭐가 있는지 몰라요. "프로젝트 내용을 꼼꼼하게 분석해 줘"라고 하면:

- 4개의 에이전트를 동시에 띄워서 모듈별/패키지별 병렬 분석
- Git 히스토리 살펴보기
- 소스 코드 전체 분석

> 분석한 내용은 세션 내 컨텍스트에 올라가서, 이후 요구사항 처리 시 참고됩니다.

## 11. 프롬프트 엔지니어링 팁 [1:05:37]

### 클로드 코드 소스에서 발견한 기법들

- **중요한 지시는 3곳에 반복**: 프롬프트 앞, 중간, 끝에 같은 내용을 넣으면 무시될 확률이 줄어듦
- **XML 태그**로 요구사항을 구조화하면 AI가 더 잘 이해
- **"CRITICAL"** 같은 강조 키워드 사용
- **조건부 프롬프트**: 상황에 따라 다른 지시를 선택하게 하는 방식

> 바이브 코딩을 하건 에이전틱 코딩을 하건, 여러분은 **프롬프트 엔지니어링에 대해서 항상 주의를 기울이고** 가이드 문서를 자주 들여다보세요.

### 유저 레벨 CLAUDE.md 설정 (실전)

저는 두 가지만 남겨놨습니다:
1. **도구 사용 시 아이콘 표시** - 어떤 도구를 쓰는지 명확하게 보려고
2. **한국어 → 영어 변환** - 입력은 한국어로 하되 최종 프롬프트는 영어로 (속도, 비용, 품질 모두 유리)

## 12. 디테일의 중요성 [1:00:32]

작은 단위로 쪼개서 개발해도 디테일이 부족한 경우가 많습니다. 왜 그럴까요?

- 완성되어야 하는 제품의 **상세한 기능을 떠올리지 못하기** 때문
- 바이브 코딩 잘하는 분들은 오히려 **기획자(PM)** 출신이 많음 - 요구사항을 상세하게 파악할 줄 알아서

> **구체적이면 구체적일수록, 명확하면 명확할수록** AI가 잘 만듭니다. 계획을 세울 때 AI 도움을 받으면 우리가 미처 생각하지 못했던 부분들을 많이 제안해 줍니다.

## 13. 스킬 관리 팁 [1:03:36]

### 남의 스킬을 내 것으로

1. 새 스킬 설치 → AI한테 "이 스킬 자세히 분석하고 설명해 줘" 요청
2. 써보면서 원하는 대로 안 되는 부분 발견
3. **Skill Creator**로 "이 스킬에서 이 부분 바꿔 줘" 요청
4. 원하는 방식으로 동작할 때까지 계속 업데이트
5. 수정한 건 **내 플러그인으로 별도 관리**

### 스킬 호출 방식

- **자동 호출**: AI가 프롬프트를 보고 매칭되는 스킬을 판단해서 실행 (비결정적)
- **슬래시 커맨드**: `/skill-name` 으로 직접 호출 (확실함)
- 원치 않는 스킬이 호출될 때: "이 스킬을 사용하지 말아 줘"라고 명시

## 14. 마무리 [1:08:39]

### 핵심 정리

1. **워크플로우 도구를 상황에 맞게 선택**: 플랜 모드(간단) / Ralph PRD(중간) / Superpowers(큰 작업)
2. **Ralph Loop**으로 AI가 중도 포기하는 문제 해결 - 완료 조건 충족까지 반복
3. **스킬은 계속 업데이트** - 모델 버전업 시 재검증 필요
4. **프롬프트 엔지니어링** 지속 학습 필요
5. AI가 코드를 만들지만, **개발은 사람이 한다** - 디테일한 요구사항을 잘 전달하는 능력이 핵심

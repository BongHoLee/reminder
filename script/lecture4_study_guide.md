# 클로드 코드 실전 2: Ralph PRD/루프, 프롬프트 엔지니어링 — 학습 가이드

> 강의: 토비의 라이브코딩 4회차 (약 1시간 10분)
> 주제: Ralph PRD + Ralph Loop 워크플로우, 오마이 클로드 코드, 프롬프트 엔지니어링 팁
> 학습 초점: **Ralph를 활용한 유저 스토리 기반 개발 + 반복 루프의 원리와 실전 적용**

---

## Part A. 시청 전 — 프리뷰

> 4회차는 시리즈의 보너스 편입니다. 3회차까지의 워크플로우 도구(플랜 모드, Superpowers)에 더해
> **Ralph의 PRD + 루프 방식**이라는 세 번째 워크플로우 도구를 익히고,
> AI가 중간에 멈추는 문제를 해결하는 **Ralph Loop**의 원리를 이해합니다.

### 이 강의에서 얻을 수 있는 것

- Ralph PRD: 유저 스토리 + 인수 조건 기반의 간결한 스펙 작성
- Ralph Loop: "완료될 때까지 반복"시키는 루프 워크플로우의 원리와 적용
- dangerously-skip-permissions 모드의 실전 사용과 주의점
- 오마이 클로드 코드의 HUD(스테이터스 라인)와 입문 시기 판단
- 프롬프트 엔지니어링 실전 팁 (클로드 코드 소스에서 발견된 기법들)
- 워크플로우 도구 3가지의 최종 사용 분기점 정리

### 에이전틱 프로그래밍 핵심 원칙 5가지

| # | 원칙 | 왜? | 적용 시점 |
|---|------|-----|-----------|
| 1 | **AI가 멈추면 루프로 밀어붙여라** | AI는 작업이 길어지면 중간에 중단해버림. 완료 조건을 명시하고 반복시키면 끝까지 해냄 | 작업이 크거나, AI가 중간에 멈출 때 |
| 2 | **유저 스토리와 인수 조건으로 스펙을 쪼개라** | 기능 단위가 아닌 유저 관점으로 스펙을 쪼개고, 각각에 완료 기준을 주면 AI가 검증하면서 작업 가능 | 기능 개발 시작 전 |
| 3 | **워크플로우 도구는 작업 규모에 맞게 골라 써라** | 플랜 모드(간단) / Ralph PRD(중간) / Superpowers(큰 기능). 모든 상황에 하나만 쓰면 비효율적 | 매 작업 시작 시 |
| 4 | **구체적이고 명확할수록 결과가 좋다** | AI에게 "만들어줘"만 하면 유치한 수준의 결과. 계획 단계에서 구체화할수록 품질 향상 | 프롬프트 작성 시 항상 |
| 5 | **스킬은 설치 후 반드시 분석 → 이해 → 커스텀하라** | 남이 만든 스킬을 그냥 쓰면 왜 그렇게 동작하는지 모름. AI에게 분석 요청 → 이해 → 필요시 수정 | 새 스킬/플러그인 도입 시 |

| 중간 규모 기능 추가 (로그아웃, 통계 등) | **Ralph PRD** (`/prd`) | 30분~1시간 | 질문 한 번, 유저 스토리 + 인수 조건 |
| 큰 기능, 새 프로젝트, 복잡한 리팩터링 | **Superpowers** (`/brainstorming`) | 1~3시간 | 9단계, 명확화 질문 반복, 비주얼 컴패니언 |
| 완료까지 오래 걸리는 작업 | **Ralph Loop** (`/ralph-loop`) | 수시간 | 완료 조건까지 자동 반복 |
| 테스트 커버리지/품질 목표 달성 | **Ralph Loop** (조건 기반) | 수시간 | "90% 될 때까지 반복" 등 |

### Ralph PRD → Ralph Loop 워크플로우

```
1. /prd "기능 설명" → 유저 스토리 + 인수 조건 생성
   ↓
2. 검토 & 수정 — 유저 스토리가 적절한지, 인수 조건이 충분한지
   ↓
3. /ralph → PRD를 JSON으로 변환 (각 스토리에 pass: false)
   ↓
4. PROMPT.md 준비 — 루프 프롬프트 작성
   ↓
5. /ralph-loop @PROMPT.md --completion-promise "COMPLETE" --max-iterations 30
   ↓
6. AI가 유저 스토리를 하나씩 완료하며 pass: true로 갱신
   ↓
7. 모든 스토리 완료 → COMPLETE 출력 → 루프 종료
   ↓
8. 결과 리뷰 + 커밋
```

### 프롬프트 엔지니어링 실전 팁 (클로드 코드 소스에서 발견)

| 기법 | 설명 | 예시 |
|------|------|------|
| **3곳 반복** | 정말 중요한 지시는 프롬프트 앞/중간/끝에 3번 넣기 | `IMPORTANT: ...` 을 3곳에 배치 |
| **XML 태그 강조** | `<critical>` 등 태그 안에 핵심 지시 넣기 | `<critical>절대 rm -rf 사용 금지</critical>` |
| **대문자 강조** | 중요 단어를 대문자로 | `NEVER`, `ALWAYS`, `CRITICAL` |
| **도구 아이콘** | 도구 사용 시 앞에 아이콘 붙이게 하기 | CLAUDE.md에 "도구 사용 시 앞에 이모지 붙여줘" |
| **영어 프롬프트** | 한국어 입력 → 영어로 변환 후 전송 | CLAUDE.md에 "한국어를 좋은 영어로 변환해서 사용" |

# 클로드 코드 심화: 도구, 스킬, 에이전트 팀 — 학습 가이드

> 강의: 토비의 라이브코딩 2회차 (약 1시간 35분)
> 주제: 클로드 코드의 동작 원리 이해 + 스킬/에이전트/에이전트 팀 활용
> 학습 초점: **에이전틱 프로그래밍의 내부 원리를 이해하고, 자신만의 도구 세트를 구축하는 방법**

---

## Part A. 시청 전 — 프리뷰

> 이번 강의는 1회차와 달리 "코드를 만드는 것"보다 **"도구를 만드는 것"**에 초점이 있습니다.
> 클로드 코드가 내부적으로 어떻게 동작하는지 이해하면, AI를 더 정밀하게 제어할 수 있습니다.

### 이 강의에서 얻을 수 있는 것

- 에이전틱 루프의 동작 원리 (컨텍스트 → 액션 → 검증 → 반복)
- 클로드 코드가 가진 **기본 도구 목록**과 각각의 역할
- **컨텍스트의 구조**: 시스템 프롬프트 + 대화 히스토리 + 도구 목록이 어떻게 합쳐지는지
- **스킬 만들기**: 반복 작업을 재사용 가능한 형태로 만드는 방법
- **서브 에이전트**: 컨텍스트를 오염시키지 않고 독립 작업을 수행하는 방법
- **에이전트 팀**: TDD(Red/Green/Refactor) 팀 구성 실습
- 플러그인 설치의 함정과 올바른 접근법

### 에이전틱 프로그래밍 핵심 원칙 6가지

| # | 원칙 | 왜? | 적용 시점 |
|---|------|-----|-----------|
| 1 | **에이전틱 루프를 머릿속에 그려라** | 도구 아이콘이 깜빡일 때 "지금 AI가 어떤 도구를 쓰라고 한 건지" 이해해야 문제를 진단하고 개입할 수 있음 | 클로드 코드 사용 중 항상 |
| 2 | **기본 도구부터 파악하라** | 확장 도구(플러그인) 전에 기본 도구(Bash, Read, Write, Grep 등)를 아는 것이 선행. 기본만으로도 대부분의 개발 작업이 가능함 | 클로드 코드 처음 시작할 때 |
| 3 | **플러그인은 선별적으로 설치하라** | 무분별한 설치 → 컨텍스트 비대화 → 성능 저하 → 제어 불능. "에이전트 150개, 스킬 1500개" 설치는 재앙 | 플러그인 설치를 고려할 때 |
| 4 | **3번 반복하면 스킬로 만들어라** | 반복되는 프롬프트를 매번 타이핑하는 것은 코드에서 함수를 안 만드는 것과 같음 | 동일한 프롬프트를 3번째 쓸 때 |
| 5 | **컨텍스트를 보호하라** | 대화 히스토리가 길어지면 AI 성능이 떨어짐. 현재 작업과 무관한 내용은 서브 에이전트로 분리해서 컨텍스트를 깔끔하게 유지 | 코드 리뷰, 품질 분석 등 부수 작업 시 |
| 6 | **자기만의 도구 세트를 점진적으로 구축하라** | 남의 도구를 통째로 가져오면 이해 없이 쓰게 됨. 하나하나 필요에 의해 만들고, 모델 업데이트 시 재검토해야 함 | 지속적으로 |

## Part C. 시청 후 — 정리 & 실습

### 핵심 개념 정리

#### 1. 에이전틱 루프

```
사용자 프롬프트
    ↓
[컨텍스트 수집] ← 시스템 프롬프트 + 대화 히스토리 + 도구 목록
    ↓
클로드 코드 → 클로드(AI)에게 전송
    ↓
클로드(AI): "이 도구를 사용해서 이 작업을 해라"
    ↓
클로드 코드: 도구 실행 → 결과 생성
    ↓
결과를 다시 클로드(AI)에게 전송
    ↓
(반복... 작업 완료까지)
    ↓
최종 응답
```

#### 2. 클로드 코드 기본 도구 목록

| 도구 | 역할 | 언제 주목? |
|------|------|-----------|

#### 3. 스킬 vs 에이전트 vs 에이전트 팀

| 구분 | 스킬 | 서브 에이전트 | 에이전트 팀 |
|------|------|-------------|------------|
| **본질** | 재사용 가능한 프롬프트 | 독립 세션에서 작업 수행 | 여러 에이전트가 협업 |
| **컨텍스트** | 현재 세션에 포함됨 | 분리됨 (결과만 반환) | 분리됨 (에이전트 간 소통) |
| **적합한 용도** | 프로젝트 생성, 코딩 규칙 적용 | 코드 리뷰, 품질 분석 | TDD, 복잡한 멀티스텝 작업 |
| **판단 기준** | "이후 대화에 맥락이 필요한가?" → Yes | "결과만 있으면 되는가?" → Yes | "여러 역할이 협업해야 하는가?" → Yes |

### 실전 워크플로우: 코드 품질 개선 사이클

강의에서 토비가 보여준 워크플로우를 정리하면:

```
1. 코드 퀄리티 오디터(에이전트) 실행
   → 가독성, 아키텍처, 테스트, 보안 등 다각도 분석
   → 점수 + 등급 + 이슈 목록

2. 이슈 목록을 태스크로 변환
   → 로컬: 태스크 리스트 생성
   → 팀: GitHub Issues로 등록

3. 이슈를 TDD 팀(에이전트 팀)으로 수정
   → Red: 문제를 증명하는 실패 테스트 작성
   → Green: 테스트 통과하는 최소 코드 작성
   → Refactor: 코드 정리

4. 반복 — 점수가 목표치에 도달할 때까지
```
